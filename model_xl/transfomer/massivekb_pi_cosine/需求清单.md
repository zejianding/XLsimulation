# massiveKB 谱相似度分析：需求与运行说明

更新时间：2026-10-12。代码目录：`v20_0918/transfomer/massivekb_pi_cosine/`。

运行状态：根据用户提供的服务器完成日志，本次 30,000 组、none/sqrt_clip 两域分析已完成。正式结果和统计口径见 [全流程操作说明第 16 节](全流程操作说明.md#16-本次正式运行结果2026-10-12-整理)，验证边界见 [验证记录](验证记录.md)。

后续新增的 v3 样本要求去修饰后的序列＋电荷也有 30,000 个唯一键，并预先验证 30,000 条预测成功；保留不同电荷，修饰变体只选一个原始组合。它是独立队列，详见 [v3 子集说明](v3_唯一Prosit输入子集说明.md)。下文原有抽样默认规则仍描述 v2，不能用 v2 的实际数量替代 v3 的数量。

本文定义修复后的管线。旧版输出不自动复用：旧过滤谱可能乱序、旧强度变换可能失真、旧 Prosit 缓存可能存在峰与注释错位。修复源码不等于已经重新完成 30,000 组的预测与编码。

## 1. 任务范围

任务一：抽取 30,000 个唯一 `(peptide, charge)` 组合，保存其全部真实谱；每条真实谱按 token 规则产生过滤谱，每个组合用 Prosit 产生一条预测谱。使用同一个 π-PrimeNovo encoder，计算 direct、averaged、pairwise 三类相似度并记录明细和汇总。

任务二：同组真实谱做 `i<j` 的两两比较，求组均值；额外报告同组过滤谱的两两相似度。这里是**组内**比较，不是不同 peptide 之间的比较。

“我们的谱”只指真实谱的过滤谱，不包含 V20 模型预测，不需要 V20 checkpoint。真实谱彼此的相似度是重复测量一致性基准，**不是预测相似度的数学上限**。例如两个正交单位向量彼此余弦为 0，而其单位化和向量与两者的余弦均为约 0.707。

## 2. 抽样规则和谱身份

- 从指定的 `massivekb_82c0124b_train.mgf.xz` 完整流式扫描两遍。XZ 可通过重新解压实现定位，但这里不依赖高效随机访问。
- 组合键为去除首尾空白的原始 `SEQ` 注释字符串与整数 charge。修饰不同、修饰字符串写法不同，均算不同键；不合并 I/L，不按纯骨架去重。
- **优先从 N≥3 的组中均匀随机抽取 30,000 组**；若优先池不足，选取其全部组，再从双谱组中随机补齐。默认 seed=20261010。候选键排序后抽样，保证可复现；不是按谱数加权，也不是优先挑谱数最大的组。
- 参数：`--prefer-spectra 3 --min-spectra 2 --n-groups 30000`。如需严格大于 3，使用 `--prefer-spectra 4`；如禁止双谱补齐，使用 `--min-spectra 3`。全部候选不足时失败，不悄悄减少组数。
- 第二遍保存所选组合的全部成员，保留原始峰与原始注释，新增 `SPECTRUM_ID=massivekb:<源文件谱块序号>`。因此不再宣称输出与源文件逐字节相同。
- 不依赖 TITLE 唯一性。过滤保留 SPECTRUM_ID；NPZ 保存 spectrum_ids；比较核对 ID 集合后重排，禁止按行号盲配。
- 输出沿用 `massTest.mgf`，含义就是用户要求的 massiveTest；同时生成 `massTest_groups.tsv` 和 `massTest_meta.json`。
- TSV 列：`group_id, group_file, sequence, charge, n_spectra, emitted, sampling_stratum`。JSON 记录候选池、优先/补齐数量、组大小直方图、源文件信息、两遍耗时及调试限制。
- `--dump-all-groups` 可选输出全源组计数 groups_all.csv，不是默认产物。
- `--limit-groups` 只减少抽取的完整组数，仍保留其全部成员。`--max-spectra` 限制源文件前缀，是有偏调试选项，元数据中明确记录，不用于正式统计。

结果描述的是“优先具有至少三次测量的组合”，不能直接推广到包含单谱组的整个 massiveKB。旧策略得到的 30,000 组 / 603,513 条谱只是历史结果，不是新策略统计。

## 3. 过滤、平均和 Prosit

### Token 过滤

复用 `v20_0918/dataset/TokenFilter_parallel.py` 与 `TokenTableOriginalAnalyze_massivekb_mods_precise_tokens.py`。默认 tol=0.05 Da；b/y 碎片电荷为 `1..min(3, precursor_charge)`，叠加该电荷对应的 token 偏移。

过滤选择匹配峰，不额外改变强度。并行使用有序 imap；整谱解析失败使阶段失败。主流程核对 ID 和各组计数完全一致。即使其他工具改变顺序，比较仍按 ID 对齐。过滤后无可用峰的谱保留身份，编码/评估标记无效，不把虚拟谱计入相似度。

### 平均谱

复用 `AverageSpectrum_batch.average_peaks_by_tolerance`，默认 tol=0.05 Da：峰按 m/z 排序，以簇内最小 m/z 为 anchor，合并 `[anchor, anchor+tol]`；同一谱在簇内取最大强度，组内求和除以总谱数，缺峰按 0；输出 m/z 为 anchor。

真实谱和过滤谱分别在**原始强度域求平均，再做强度变换，再编码**，不是先平均 embedding。

### Prosit

复用 `eval_10k_gt/prosit_predict_mgf.py` 和 `ds/step4_prosit_score.py`，调用 Koina `Prosit_2025_intensity_MultiFrag`，输入碎裂类型 HCD。沿用 reanchor：去修饰骨架预测强度，再按注释 b/y 重锚到带修饰的理论 m/z，合并近邻峰。这不等于模型直接预测修饰对强度的影响。

- 峰排序同步重排注释；缓存读写保持 `(mz, intensity, annotation)` 对应。
- 新缓存自动使用 `<指定缓存路径>.aligned-v2` 及其分段文件，旧缓存保留但不读取。
- 长度超过代码上限 30、请求失败、空预测、重锚/筛选后为空，分别写入 prosit_skipped.csv，键包含 sequence 和 charge。
- 成功组必须恰有一条预测谱。成功集合和跳过集合互斥且并集等于抽样集合。不保证所有 30,000 组都受 Prosit 支持，也不通过换样本隐瞒预测失败。
- `--min-mz` 默认 0，显式传值时才截去低 m/z 峰；保留有限且正强度的峰，随后仍有 PI 自带预处理。
- `--prosit-mgf` 可导入外部预测，缺失组记为 external_missing；`--skip-prosit` 明确只跑过滤谱与任务二，两者不能同时使用。

## 4. 强度域和 PI 编码

默认运行 **none 主口径 + sqrt_clip 对照口径**。每个域内，真实谱、过滤谱、Prosit 谱及平均谱使用相同变换。

- none：不额外变换强度，正确保留小数及科学计数法数值。
- sqrt_clip：精确计算 `sqrt(min(x,50000)/50000)`，不先把 x 转成整数。
- 可选 sqrt：`sqrt(x)`。

主入口 `--domains none,sqrt_clip`；Bash 环境变量 `INTENSITY_TRANSFORM=none,sqrt_clip`。不同域的数字不能混为同一比较。

编码入口 `piprime_embedding/piprime_embedding/mgf_to_embedding_batch.py`，权重由 --model / PIPRIME_MODEL 指定。`encoder_only.py` 从同一 checkpoint 严格加载完整 encoder 权重，使用原 SpectrumEncoder 架构和 `encoder(peaks).mean(dim=1)`，不引入 peptide 解码所需的 cupy/CTC 依赖。

当前 PI 配置为 400 维、m/z 1–6500、去前体 1 Da、最多 800 峰、root 缩放加 L2。实际预处理参数、包版本、模型路径与设备写入 embedding_provenance.json。主流程启用 --strict-preprocessing，必须有 spectrum_utils，禁止静默 fallback。

无可用峰写 NaN embedding 与 invalid_reasons，不使用虚拟峰；其他编码异常使阶段失败。GPU 通过 CUDA_VISIBLE_DEVICES 生效；PyTorch 无 CUDA 时使用 CPU并记录设备。

每个域五套嵌入：real、filtered、prosit、avg_real、avg_filtered。默认两个域共十套，prosit 目录只含预测谱，不混入真实谱。没有成功预测时跳过 Prosit 编码，任务二仍覆盖全部真实组。

## 5. 指标定义

组内 N 条真实谱 r_i，按 ID 对应过滤谱 f_i，一条 Prosit 谱 q。下表 cos 均指同域 PI embedding 的余弦，avg(r)/avg(f) 为平均谱。

| 指标 | filtered | Prosit |
|---|---|---|
| direct | mean_i cos(f_i,r_i) | mean_i cos(q,r_i) |
| averaged_each | mean_i cos(f_i,avg(r)) | cos(q,avg(r)) |
| averaged | cos(avg(f),avg(r)) | cos(q,avg(r)) |
| pairwise | mean_j mean_i cos(f_j,r_i)，N² 项含对应项 | mean_i cos(q,r_i) |

模式二同时报告 filtered 的两种口径；Prosit 在两行数值相同，不作为两项独立证据。Prosit pairwise 恒等于 direct。

另保存每条过滤谱对整组真实谱的均值和 filtered 非对应项均值。不能仅凭 pairwise 高于/低于 direct 就判定覆盖了全部个体变异。

任务二用 `i<j`，不含自配对、不重复计数，共 `N(N−1)/2` 对；分别报告 real-real 与 filtered-filtered 的 mean/min/max。另报真实谱对真实平均谱的基准 orig_vs_avg。N=1 的全交叉仍有定义，但无自配对的任务二无定义；本任务抽样 N≥2。

### 有效性和汇总

- 缺文件、谱数不符、重复/缺失 ID、非本组谱、文件与 NPZ 身份不符，直接失败。
- 无可用峰等数据无效情况保留 NaN、原因和 n_valid_values；一个组的某指标只有全部预期比较项有效才进入该指标汇总，不对有效子项偷偷缩小分母。
- all 报告该源该指标的预期、有效、无效组数。
- paired 按“同域、同指标、两源均有效”的组交集计算，双方组分母相同。
- 分桶 N=2 / 3–5 / 6–10 / >10，并报告 paired 内分桶。任务二不依赖 Prosit，不因预测失败丢真实组。
- group：每个有效组一票。
- pooled：总相似度之和除以比较项数。direct 权重 N；filtered pairwise 权重 N²；Prosit pairwise 权重 N；任务二权重 N(N−1)/2；平均谱对平均谱每组一项；逐谱对平均谱权重 N。
- 两种权重各报 mean/std。p10/median/p90 明确是 group 行的组均值分布；pooled 分位数留空并标记 not_reported，不把组均值分位数冒充所有谱对分位数。全部原始谱对值保留供额外分析。

## 6. 输出契约

每个域的 `metrics_<domain>-.../` 产出：

| 文件 | 内容 |
|---|---|
| mode1_direct.csv | 每条真实谱的两源 direct、spectrum_id、无效原因 |
| mode2_averaged.csv | 每组 filtered-avg、filtered-each、Prosit、orig_vs_avg_mean |
| mode2_filtered_detail.csv | 每条过滤谱/真实谱对真实平均谱的值 |
| mode3_pairwise.csv | 每组两源全交叉均值和 filtered 非对应项均值 |
| mode3_filtered_means.csv | 每条过滤谱对整组真实谱的均值 |
| mode3_pairs.csv.gz | 全部 N² 过滤谱×真实谱对及两个谱 ID |
| task2_within_group.csv | 每组两种组内相似度 mean/min/max、n_pairs |
| task2_pairs.csv.gz | 全部 i<j 的 real-real 与 filtered-filtered |
| group_metrics.csv | 每源×指标×组的统计量及有效性 |

结果均含 group_file、sequence、charge、domain。Prosit pairwise 的逐谱值复用 direct 明细，不重复写相同数据。

最终汇总阶段输出 summary.csv 和 task2_summary.csv。根目录 run_manifest.json 给出状态、参数和各阶段实际目录，勿猜带指纹的目录名。stage_manifest.json 记录参数、依赖、代码与产物 SHA256。

## 7. 运行顺序与续跑

入口为 run_pipeline.py；run_massivekb_pi_cosine.sh 只负责环境变量适配。Windows 可直接用 Python，无须 Bash。

1. sample_massivekb_test.py：两遍抽样、写 ID、核对组数和谱数。
2. TokenFilter_parallel.py：过滤并验证全部谱身份。
3. prosit_predict_mgf.py：预测/导入并核对成功/失败分区。
4. build_groups.py：分别分组 real、filtered、prosit。
5. grouped_to_average_mgf.py：原始强度域求 real、filtered 平均谱。
6. 每个域：transform_mgf_intensity.py → 五套 mgf_to_embedding_batch.py → pairwise_cosine.py。
7. summary_all.py：各域三类比较和任务二汇总。

阶段在新的 .partial-* 目录构建，校验后提交，旧结果保留。复用必须匹配参数、依赖、代码和包版本，并核对全部产物内容指纹。损坏/缺失时重建，失败阶段没有成功状态。--force / FORCE=1 在新目录重建。独立组件通常是构建器，续跑由主入口管理，不再宣称每个脚本都能单独断点续跑。

巨大源 XZ 使用路径、大小、修改时间标识，并在两遍后复核；其余阶段输入输出使用内容指纹。输入应视为不可变；如果人为保留大小和时间戳修改 XZ，需用新路径或 --force。

### 分阶段与小样

- 仅抽样：加 --stop-after sample，无需 checkpoint、Prosit 或编码依赖。
- 准备到分组/平均：--stop-after prepare；暂不联网可加 --skip-prosit，之后取消它继续。
- 小样：新输出目录加 --limit-groups 10，扫描全源并保留所选组全部谱。快速解析调试可额外 --max-spectra 200000，但只能视为有偏前缀样本。
- 跨机器复用新样本：--sample-dir <三件套目录> 代替 --train-mgf-xz，会验证 schema、优先策略、组数和 ID。旧 2026-10-10 样本不满足新规格，须重抽。
- Bash 变量：OUT_DIR、TRAIN_MGF_XZ、SAMPLE_DIR、PIPRIME_MODEL、N_GROUPS、MIN_SPECTRA、PREFER_SPECTRA、SEED、THREADS、WORKERS、GPU、TOL_FILTER、TOL_AVERAGE、INTENSITY_TRANSFORM、LIMIT_GROUPS、PROSIT_CACHE、PROSIT_MGF、SKIP_PROSIT、STOP_AFTER、FORCE。SKIP_SAMPLE=1 必须提供 SAMPLE_DIR；MAX_SCANS 已移除，使用 LIMIT_GROUPS。
